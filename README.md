# architecture-alexandrite (Sprint 6)

В этом спринте подготовлены архитектурные решения по наблюдаемости и производительности для системы Alexendrite (Shop API / CRM / MES / RabbitMQ).

Что сделано по задачам

Task1 (Планирование): зафиксированы проблемы (рост заказов, задержки MES, риски интеграции через очередь), сформированы инициативы и приоритизация на ~6 месяцев.

Task2 (Мониторинг): выбран подход (RED для API, USE для инфраструктуры), перечислены ключевые технические и бизнес-метрики, предложены дашборды и алерты, описан план внедрения (Prometheus/Grafana/Alertmanager + exporters).

Task3 (Трейсинг): описано, где внедряем распределённый трейсинг (HTTP + RabbitMQ), какие атрибуты/корреляции (order_id, message_id, trace_id), предложен стек на OpenTelemetry + Jaeger/Tempo, добавлены компромиссы и меры безопасности.

Task4 (Логирование): определён стандарт структурированных логов (JSON), уровни/события, корреляция с trace_id, выбран pipeline (Fluent Bit/Vector → Loki/OpenSearch → UI), описаны требования по PII и хранению.

Task5 (Кеширование): предложено кеширование данных для MES dashboard (Cache-Aside для чтения, обновление при записи статуса/событиях), описаны ключи/TTL и инвалидация; добавлены sequence-диаграммы чтения и обновления статуса.

Где смотреть артефакты

Все материалы разложены по папкам Task1 … Task5.

Диаграммы:

Mermaid-диаграммы встроены в .md файлы.

Sequence-диаграммы для кеширования лежат в Task5 (*.puml / или *.svg, если экспортировано).
